# 庄方宜交互桌面概念 v2

日期：2026-09-15。此稿为内置 imagegen 生成的视觉概念，不是已应用到手机的界面，也不是已完成的 Live2D 模型。人物细节为重新演绎，正式素材需与用户既有庄方宜壁纸统一。

## 布局

- 取消右侧工具塔，底部只有一套主题 App Dock：电话、微信、浏览器、相机，可重新绑定。
- 斜条缩小为电量与日期信息区，文字水平排列；半透明墨绿至橄榄金渐变，保留少量金色点纹和细线。
- 从当前壁纸位图提取主色和柔和色，压低亮度和饱和度以保持文字对比。仅在壁纸更换时更新配色，避免逐帧取色。允许用户锁定配色。
- 系统底部手势区域留空；点击区域建议至少 48 dp，不能与人物热点重叠。

## 交互

- 常用 Dock 单击直接打开应用，不强制先播放人物动画。
- 点手掌：短暂手部响应与技能光标，展开扫一扫、付款码、相册。菜单内点选才跳转。
- 点发饰：微光与轻微发丝响应，展开音乐卡。
- 后续可用腰间挂件关联文件/工具，但首版只做两个热点，避免页面过于复杂。
- 点菜单外空白或开始左右滑页：关闭展开菜单；滑动必须优先于人物点击，不在滑动抬手时误触应用。
- 热点位置随人物位移与动画同步。首用提示位置，平时保留极轻微光点。
- 非主题页保留主题 Dock 的可用性，人物热点仅在主题页启用；原有斜条随翻页收拢逻辑保留。

## 实现范围与验证点

1. 当前 KLWP：位图取色、渐变、透明度、热点、全局状态驱动的位移/缩放/旋转/渐隐、App 绑定可先做。分层与预绘姿态可模拟局部动画，但不能当作真实手部翻转。
2. 真正翻掌：需要拆分前臂/手腕/手掌/手指，补画隐藏区域，制作关节和形变及专门翻掌姿态。现有 PNG 不是可直接使用的 Live2D 模型。
3. 高品质多人身热点动画建议单独制作 Android 动态壁纸程序，使用 Cubism 或其它二维骨骼/序列帧渲染。Android 提供壁纸触控和偏移接口，但与 HyperOS 的触摸传递、翻页和 App 启动必须用真机验证。不能保证换渲染器后自动解决桌面限制。
4. 移除 HyperOS 固定 App 图标并不代表其 Dock 触摸区域自动释放。应先验证主题底部入口能可靠收到点击，再替换系统 Dock；若系统保留区域拦截，调整主题入口到有效区域或另外评估桌面支持。
5. 新方案需要实测电量消耗、触控响应、模型内存和动画帧率。界面不可见时停动画，降低待机光效频率，禁止持续逐帧取色。
